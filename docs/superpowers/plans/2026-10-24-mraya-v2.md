# Mraya v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Budget-true recommendations with real product images/links (Serper), history/delete, export, avatar settings, and an Apple-style liquid-glass redesign with smooth theme blending.

**Architecture:** Analysis pipeline gains two pure/isolated stages (`shopping.enrich`, `budget.fit_to_budget`) after Gemma parsing. Storage interface gains per-analysis queries implemented in both backends. Dashboard becomes per-analysis with history, delete and export; a new `apps.settings_page` app owns the avatar. A shared component layer (`ui.css`/`ui.js`) re-creates shadcn components in plain CSS/JS; glass is reserved for the controls layer.

**Tech Stack:** Django 5.1, google-genai (Gemma 4), Serper.dev shopping API via `urllib.request`, Pillow, Firestore / local JSON store, vanilla CSS/JS, Lucide icons (inline SVG), Inter + Montserrat (Google Fonts).

**Spec:** `docs/superpowers/specs/2026-10-24-mraya-v2-design.md`

## Global Constraints

- **No `git commit` / `git push` at any step.** Leave all changes in the working tree; the user runs locally first.
- No new Python dependencies (`requirements.txt` unchanged). No React, no npm.
- Run tests with: `.venv/Scripts/python.exe manage.py test` (all 49 existing tests must keep passing).
- Tests never hit the network: Serper and Gemma are always stubbed.
- `SERPER_API_KEY` optional; missing key → fallback behaviour, never an error.
- Category budget weights: clothing 35, shoes 20, perfume 15, skincare 12, hair 10, accessories 8 (re-normalised to chosen categories).
- Serper: `POST https://google.serper.dev/shopping`, header `X-API-KEY`, body `{"q", "gl"}`; max 8 workers; 6 s timeout; primary `gl` = the user's `country` (default `ma`); abroad order: `ma` → `["fr", "us"]`, every other country → `["us"]`.
- Countries (`apps/analysis/countries.py`): MA, FR, ES, BE, GB, US, CA, AE, SA, DE, IT, NL. Default currency: MA→MAD, FR/ES/BE/DE/IT/NL→EUR, GB→GBP, US→USD, CA→CAD, AE→AED, SA→SAR.
- Fixed rates in `currency.py`, expressed as MAD per unit: MAD 1, EUR 10.8, USD 9.9, GBP 12.7, CAD 7.2, AED 2.7, SAR 2.64.
- Abroad note copy (exact): "Price may not include shipping or customs."
- Product links open with `target="_blank" rel="noopener noreferrer"`; product images use `loading="lazy" referrerpolicy="no-referrer"`.
- Theme transition ~0.8 s via `@property` colour tokens; all motion disabled under `prefers-reduced-motion: reduce`.
- WCAG AA text contrast in neutral, men and women themes.
- Every new URL is behind `login_required` and only serves the signed-in user's data (another user's id → 404).

## Review Focus

1. Serper price strings in the wild (`"MAD\xa094.09"`, `"€7.49"`, `"1 299,00 MAD"`, `"$12.99/month"`, `"Free"`) → parsed to the right number and currency, or treated as no price. (Task 1)
2. Budget smaller than the cheapest product of a category → that category keeps its advice, shows "No pick fits your budget", and `budget.used ≤ budget.limit` always. (Task 2, Task 7)
3. Remote image fails to load (hotlink blocked, 404) → card shows the category icon, not a broken image. (Task 7)
4. Analyses saved before v2 (no `budget`, `link`, `image_url`, per-analysis thumbs) → dashboard, history and export render without errors. (Task 6, Task 7)
5. Deleting the analysis currently shown, or an id that doesn't exist → redirect to the next analysis / home, or 404; never a 500. (Task 6)

```python
def p(cat, price, priority="nice"):
    return {"category": cat, "price": price, "priority": priority, "name": f"{cat}-{price}"}

class BudgetTests(SimpleTestCase):
    def test_allowances_renormalise(self):
        a = category_allowances(1000, ["clothing", "shoes"])
        self.assertEqual(a, {"clothing": 636.36, "shoes": 363.64})

    def test_over_budget_keeps_one_per_category_first(self):
        kept, s = fit_to_budget([p("clothing", 600), p("clothing", 300), p("shoes", 500), p("shoes", 200)], 600, "MAD")
        self.assertEqual(sorted(x["name"] for x in kept), ["clothing-300", "shoes-200"])
        self.assertEqual(s, {"limit": 600, "used": 500, "currency": "MAD", "dropped": 2})

    def test_essential_before_nice(self):
        kept, _ = fit_to_budget([p("hair", 50), p("hair", 100, "essential"), p("hair", 90)], 160, "MAD")
        self.assertEqual(sorted(x["name"] for x in kept), ["hair-100", "hair-50"])

    def test_unpriced_kept_not_counted(self):
        kept, s = fit_to_budget([p("perfume", None), p("perfume", 100)], 100, "MAD")
        self.assertEqual(len(kept), 2)
        self.assertEqual(s["used"], 100)

    def test_category_too_expensive_is_dropped_and_used_never_exceeds_limit(self):
        kept, s = fit_to_budget([p("perfume", 900), p("hair", 80)], 100, "MAD")
        self.assertEqual([x["name"] for x in kept], ["hair-80"])
        self.assertLessEqual(s["used"], s["limit"])

    def test_exact_fit(self):
        kept, s = fit_to_budget([p("shoes", 250), p("shoes", 250)], 500, "MAD")
        self.assertEqual((len(kept), s["used"], s["dropped"]), (2, 500, 0))
```

Pass 2: remaining priced products sorted by `(priority != "essential", price)`, added while they fit. Unpriced always kept. Kept list returned in the original input order.
